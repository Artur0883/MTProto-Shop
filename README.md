# MTProto Shop

Минимальный Telegram-магазин доступа к MTProto proxy для VPS.

## Что сейчас есть

- Telegram-бот на `aiogram 3.x`.
- SQLite-база пользователей и подписок.
- MTProto proxy через TeleMT (`ghcr.io/telemt/telemt:latest`).
- Один клиент = один личный `secret`.
- Личная ссылка собирается на лету из `SERVER_HOST`, `PROXY_PORT` и `secret`.
- В сообщениях клиента длинная ссылка/IP не показывается: клиент видит кнопку **🔐 Подключиться к MTProto**.
- Поддержка может работать через отдельный support-бот или как fallback внутри основного бота.
- VPS-меню `manage.sh` для запуска, логов, ключей, бэкапа и пересоздания контейнеров.

## Переменные окружения

Скопируйте пример:

```bash
cp .env.example .env
```

Заполните:

```env
BOT_TOKEN=123456:telegram_bot_token
SUPPORT_BOT_TOKEN=654321:support_bot_token
ADMIN_ID=123456789
SERVER_HOST=1.2.3.4
PROXY_PORT=443
TLS_DOMAIN=protovich.ru
PROXY_CORE=telemt
TELEMT_API_URL=http://mtproto:9091
TELEMT_SYSTEM_USER=shop_bootstrap
SUPPORT_CONTACT=
DATABASE_PATH=/app/data/shop.db
PAYMENT_MODE=manual
DEV_AUTO_ISSUE=false
```

`SUPPORT_CONTACT` можно оставить пустым. Тогда при нажатии **🆘 Поддержка** обращение обрабатывает основной бот.

Для отдельного двустороннего бота поддержки укажите его username и отдельный токен:

```env
SUPPORT_CONTACT=@your_support_bot
SUPPORT_BOT_TOKEN=654321:support_bot_token
```

Клиент перейдёт в support-бота и напишет вопрос там. Администратор должен один раз открыть этот support-бот и нажать `/start`, после чего ответы через reply на сообщения клиента будут доставляться обратно клиенту.

`BOT_TOKEN` и `SUPPORT_BOT_TOKEN` должны быть токенами разных ботов. В `SUPPORT_CONTACT` указывается только `@username` или ссылка, не токен.

## Оплата

Режим оплаты задаётся через `PAYMENT_MODE`:

- `manual` — клиент отправляет заявку оператору, администратор подтверждает оплату и выдаёт доступ кнопкой в Telegram.
- `stars` и `crypto` — зарезервированы для следующих фаз; сейчас также переводят клиента к оператору.
- `auto_free` — автоматическая бесплатная выдача платного доступа, только для разработки.

**Никогда не используйте `PAYMENT_MODE=auto_free` в продакшене.** Этот режим срабатывает только вместе с `DEV_AUTO_ISSUE=true`. Безопасные настройки по умолчанию: `PAYMENT_MODE=manual` и `DEV_AUTO_ISSUE=false`.

Пробный тариф на 1 день с ценой `0` выдаётся автоматически во всех режимах.

## Быстрая установка с нуля

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Artur0883/MTProto-Shop/main/install.sh)
```

Установщик поддерживает Ubuntu/Debian, размещает проект в `/opt/mtproto-shop`, устанавливает Docker при необходимости и создаёт команду:

```bash
mtp
```

После открытия меню выберите:

```text
1) 🧙 Первичная установка с нуля
```

Мастер проверит токен через Telegram API, создаст `.env` и `telemt/config.toml`, затем выполняет запуск в два этапа:

1. Запускает только TeleMT и проверяет его API внутри compose-сети.
2. После успешной проверки TeleMT запускает основной Telegram-бот и support-бот.

При успешной установке бот должен получить `healthy`-статус, а в его логах появится `Start polling`.

Проверка установленного проекта:

```text
21) 🧪 Проверка установки
```

## Файлы и управление

- Проект: `/opt/mtproto-shop`
- Настройки и токены: `/opt/mtproto-shop/.env` с правами `0600`
- Меню управления: `mtp`
- Логи основного бота: `mtp` → `4) 📄 Логи бота`
- Перезапуск проекта: `mtp` → `17) 🔁 Пересоздать ботов + MTProto proxy`
- Бэкап: `mtp` → `14) 💾 Сделать бэкап`

Для уже настроенной установки обновление кода и пересоздание контейнеров выполняется через `mtp` → `2) 🚀 Установка / обновление / запуск`.

`manage.sh` содержит:

```text

4) 📄 Логи бота
5) 📄 Логи TeleMT
6) 📋 Список ключей
7) ➕ Добавить ключ вручную
8) 🔄 Обновить ключ клиента по Telegram ID + синхронизировать SQLite
9) 🔗 Показать ссылку по Telegram ID
10) 🔗 Показать ссылку по client_id
11) ❌ Удалить ключ по client_id
12) ♻️ Проверить TeleMT API / применить изменения
13) ⚙️ Открыть .env
14) 💾 Сделать бэкап
15) 🔁 Пересоздать Telegram-ботов
16) 🔁 Пересоздать MTProto proxy
17) 🔁 Пересоздать ботов + MTProto proxy
18) 🖥️ Перезагрузить VPS полностью
19) 📄 Логи бота поддержки
20) 🛡 Установить watcher автоматического рестарта
21) 🧪 Проверка установки
0) 🚪 Выход
```

Пункт 2 сначала выполняет безопасное обновление кода через `git pull --ff-only origin main`, а затем пересобирает контейнеры. Если локальный файл мешает обновлению, сборка старой версии отменяется и меню показывает команду для диагностики.

Пункты 1, 2, 15 и 17 используют `--force-recreate`, чтобы новые значения из `.env` точно применялись. Пункты 15 и 17 пересоздают и основной бот, и отдельный support-бот. Файлы `.env`, `data/`, `backups/` и `logs/` не загружаются из Git и сохраняются на VPS.

## Клиентские кнопки

- 🛒 Купить доступ
- 🔑 Мой прокси
- 📅 Моя подписка
- 🆘 Поддержка

Клиент пишет `/start` один раз: после этого Telegram сохраняет нижнее меню, и повторно вводить команду для обычных действий не требуется. Старые кнопки **💳 Купить доступ**, **🚀 Купить доступ**, **🔐 Подключиться**, **🔗 Моя ссылка**, **⏳ Моя подписка**, **⏳ Срок доступа**, **📅 Осталось дней**, **📖 Инструкция**, **🆘 Помощь** и **💬 Поддержка** тоже поддерживаются, чтобы не ломать ранее показанную клавиатуру.

## Сценарий нового клиента

1. Клиент нажимает `/start` один раз и получает постоянное меню.
2. Нажимает **🛒 Купить доступ**, выбирает пробный тариф и получает личный ключ на 1 день.
3. На экране активации нажимает **🔐 Подключиться к MTProto**.
4. В дальнейшем открывает ключ кнопкой **🔑 Мой прокси**, а срок действия — кнопкой **📅 Моя подписка**.

Пробный день выдаётся один раз. После его использования бот предлагает выбрать платный тариф.

## Обновление ключа клиентом

Клиент открывает **📅 Моя подписка** и нажимает **🔄 Обновить ключ**. При активной подписке бот выдаёт новую кнопку подключения, а старый ключ перестаёт работать после применения изменений proxy.

Новые ссылки выдаются в формате `ee...` с TLS-маскировкой. Ранее выданные ссылки `dd...` продолжают работать до обновления ключа.

Ключ можно обновлять не чаще одного раза в 10 минут.

## 🛰 TLS-маскировка и выбор TLS_DOMAIN

На мобильных сетях чистый MTProto-secure-трафик из ссылок `dd...` может распознаваться DPI, из-за чего подключение затягивается или обрывается. TLS-режим выдаёт ссылки `ee...` и маскирует соединение под обычный HTTPS, поэтому подключение должно стать быстрее и стабильнее.

По умолчанию мастер использует `TLS_DOMAIN=protovich.ru`: этот вариант ближе к стандартной установке TeleMT и может лучше работать на iOS.

`TLS_DOMAIN` должен быть стабильно доступен из РФ и иметь валидный TLS-сертификат. Альтернативные варианты:

- `protovich.ru` — значение по умолчанию
- `www.cloudflare.com`
- `www.microsoft.com`
- `www.bing.com`
- `www.apple.com`
- `dl.google.com`

Не используйте `www.google.com`, поскольку он может быть плохо доступен в РФ. Также не используйте домен, который уже находится под блокировкой.

## Ручные команды

Показать статус:

```bash
docker compose ps
```

Логи бота:

```bash
docker compose logs -f --tail=120 bot
```

Логи отдельного бота поддержки:

```bash
docker compose logs -f --tail=120 support_bot
```

Логи proxy:

```bash
docker compose logs -f --tail=120 mtproto
```

Пересоздать оба контейнера:

```bash
docker compose up -d --build --force-recreate bot support_bot mtproto
```

Обновить ключ клиента по Telegram ID и синхронизировать SQLite:

```bash
docker compose exec bot python proxy_manager.py rotate-telegram 123456789
```

Проверить TeleMT API после изменения ключей:

```bash
docker compose exec bot python -c "import urllib.request,json; print(json.loads(urllib.request.urlopen('http://mtproto:9091/v1/users',timeout=3).read()))"
```

## Важные файлы

- `bot/client.py` — клиентское меню, покупка, подключение, поддержка.
- `bot/admin.py` — админ-меню, выдача, продление, обновление и отключение доступа.

- `bot/keyboards.py` — кнопки и клавиатуры.
- `bot/tariffs.py` — тарифы и статусы включён/в разработке.
- `bot/proxy_manager.py` — создание, удаление, обновление ключей.
- `telemt/config.toml` — runtime-конфигурация TeleMT, создаётся мастером установки.
- `manage.sh` — меню управления на VPS.
- `.env.example` — безопасный пример настроек без реальных секретов.

## Безопасность

- Реальный `.env` не хранить в GitHub.
- Базу `data/shop.db` не хранить в GitHub.
- Если токен бота попал на скрин или в чат — перевыпустить его через `@BotFather` → `/revoke`.

## 🔁 Перезагрузка из админ-панели бота

Кнопка **🔁 Перезагрузка системы** в админ-меню пересоздаёт основной бот, бот поддержки и MTProto-прокси. На время перезапуска клиенты могут потерять соединение примерно на 30 секунд.

Чтобы кнопка работала, один раз установите watcher на VPS: откройте `mtp` и выберите пункт `20` — **🛡 Установить watcher автоматического рестарта**.

Если watcher ещё не установлен, кнопка ничего не сломает: бот через 10 секунд покажет предупреждение с инструкцией по установке.

## 🛡 Состояние системы

Кнопка **🛡 Состояние системы** показывает в админ-меню, работают ли основной бот, бот поддержки, MTProto-прокси и автоматическая перезагрузка. Там же видны количество клиентов и подписок, свободное место, память и время последнего рестарта через бота.

Отчёт помогает быстро понять, нужен ли вход на VPS для проверки или восстановления сервисов.
