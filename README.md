# MTProto Shop

Минимальный Telegram-магазин доступа к MTProto proxy для VPS.

## Что сейчас есть

- Telegram-бот на `aiogram 3.x` с типизированным конфигом (`pydantic-settings v2`) и structlog-логами.
- SQLite-база пользователей и подписок.
- MTProto proxy через TeleMT (`ghcr.io/telemt/telemt:latest`), интеграция через HTTP API (`aiohttp`).
- Один клиент = один личный `secret`.
- Личная ссылка собирается на лету из `SERVER_HOST`, `PROXY_PORT` и `secret`.
- В сообщениях клиента длинная ссылка/IP не показывается: клиент видит кнопку **🔐 Подключиться к MTProto** + кнопку **🌐 Альтернативные ссылки**.
- **Устойчивость к РКН:** автоматический выбор лучшего TLS-домена, fallback на резервные домены (`TLS_DOMAINS`), кнопка «альтернативные ссылки» для клиентов в зонах с DPI-блокировками.
- **Отказоустойчивость:** circuit breaker для TeleMT API, retry с decorrelated jitter, cooldown на ротацию ключа, graceful degradation при сбоях TeleMT.
- Поддержка может работать через отдельный support-бот или как fallback внутри основного бота.
- VPS-меню `manage.sh` для запуска, логов, ключей, бэкапа и пересоздания контейнеров.

## Устойчивость к РКН / DPI

MTProto-Shop использует TLS-маскировку (`tls_emulation = true` в TeleMT): трафик с прокси
выглядит как обычный HTTPS до выбранного домена. Это блокируется только если РКН
заблокирует конкретный домен у конкретного оператора. Чтобы это не выводило весь сервис из строя:

1. **Несколько fallback-доменов.** Укажите список в `.env` как
   `TLS_DOMAINS=a.com,b.com,c.com` и тот же набор в
   `telemt/config.toml` как `tls_domains = ["a.com", "b.com", "c.com"]`.
   TeleMT сможет принять эти Fake-TLS домены, а бот предложит ссылки через
   кнопку **🌐 Альтернативные ссылки**. Основная ссылка всегда использует `TLS_DOMAIN`.
2. **Авто-проверка.** Бот периодически (каждые 5 минут) делает реальный TLS handshake
   до каждого домена и показывает состояние доменов в диагностике. Основная ссылка
   остаётся предсказуемой и использует `TLS_DOMAIN`; резервные домены выдаются отдельно.
3. **Ротация ключа.** Клиент может нажать **🔄 Обновить ключ** в разделе
   «📅 Моя подписка». Старый ключ перестаёт работать через ~5 секунд.

### Рекомендации по выбору `TLS_DOMAIN` / `TLS_DOMAINS`

- Реальный сайт с TLS 1.3 на 443 (проверить через `openssl s_client -connect host:443 -servername host`).
- Не однотипные домены: один — крупный CDN (`www.cloudflare.com`), второй — тематический
  российский сайт (`www.kp.ru`, `www.lenta.ru`), третий — нейтральный международный.
- Избегайте доменов, заведомо популярных у других публичных MTProto-сервисов
  (они быстрее попадают в чёрные списки DPI).
- Проверяйте кандидатов через `mtp` → `25`.
- В `/admin → 🛡 Состояние системы` бот показывает текущий рейтинг доменов с latency.

## Переменные окружения

Скопируйте пример:

```bash
cp .env.example .env
```

Заполните:

```env
BOT_TOKEN=123456:telegram_bot_token
SUPPORT_BOT_TOKEN=654321:support_bot_token
ADMIN_ID=123456789
SERVER_HOST=1.2.3.4
PROXY_PORT=443

# TLS-маскировка
TLS_DOMAIN=www.microsoft.com
TLS_DOMAINS=www.cloudflare.com,www.apple.com,www.bing.com

# TeleMT API
PROXY_CORE=telemt
TELEMT_API_URL=http://mtproto:9091
TELEMT_SYSTEM_USER=shop_bootstrap
TELEMT_PROXY_INTERNAL_PORT=443

# Опционально — тонкая настройка отказоустойчивости
TELEMT_API_TIMEOUT=5.0
TELEMT_API_MAX_RETRIES=3
TELEMT_CIRCUIT_BREAKER_THRESHOLD=5
TELEMT_CIRCUIT_BREAKER_RECOVERY=30.0
TELEMT_ROTATE_COOLDOWN=30.0

SUPPORT_CONTACT=
DATABASE_PATH=/app/data/shop.db
PAYMENT_MODE=manual
DEV_AUTO_ISSUE=false
PAYMENTS_ENABLED=true

BOT_HEALTHCHECK_MAX_AGE=180
SUPPORT_BOT_HEALTHCHECK_MAX_AGE=180

# Логи: json для production, console для локалки
LOG_LEVEL=INFO
LOG_FORMAT=json
```

`SUPPORT_CONTACT` можно оставить пустым. Тогда при нажатии **🆘 Поддержка** обращение обрабатывает основной бот.

Для отдельного двустороннего бота поддержки укажите его username и отдельный токен:

```env
SUPPORT_CONTACT=@your_support_bot
SUPPORT_BOT_TOKEN=654321:support_bot_token
```

Клиент перейдёт в support-бота и напишет вопрос там. Администратор должен один раз открыть этот support-бот и нажать `/start`, после чего ответы через reply на сообщения клиента будут доставляться обратно клиенту.

`BOT_TOKEN` и `SUPPORT_BOT_TOKEN` должны быть токенами разных ботов. В `SUPPORT_CONTACT` указывается только `@username` или ссылка, не токен.

## Оплата

Продажи управляются флагом `PAYMENTS_ENABLED`:

- `true` — платные тарифы доступны согласно `PAYMENT_MODE`.
- `false` — платные тарифы отключены; действующие клиенты продолжают получать свои ссылки через **🔑 Мои ключи**, а пробный тариф остаётся доступным.

Режим оплаты задаётся через `PAYMENT_MODE`:

- `manual` — клиент отправляет заявку оператору, администратор подтверждает оплату и выдаёт доступ кнопкой в Telegram.
- `auto_free` — автоматическая бесплатная выдача платного доступа, только для разработки.
- `stars` и `crypto` — зарезервированы в коде, но пока не реализованы и не предлагаются в меню управления.

**Никогда не используйте `PAYMENT_MODE=auto_free` в продакшене.** Этот режим срабатывает только вместе с `DEV_AUTO_ISSUE=true`. Безопасные настройки по умолчанию: `PAYMENTS_ENABLED=true`, `PAYMENT_MODE=manual` и `DEV_AUTO_ISSUE=false`.

На VPS эти значения настраиваются через `mtp` → `24) ⚙️ Изменить способ оплаты`.

Пробный тариф на 1 день с ценой `0` выдаётся автоматически во всех режимах.

- 🍎 macOS native (App Store);
- 💻 Telegram Desktop (Windows / Linux);
- 📱 Telegram X;
- 🌐 Telegram Web (с пояснением, что ссылку `tg://proxy` нужно открыть в приложении).

Кнопка **✨ Инструкция для моей платформы** сразу предлагает выбрать устройство. Telegram Bot API не сообщает боту достоверную платформу клиента, поэтому бот не угадывает её автоматически.

## Сценарий нового клиента

1. Клиент нажимает `/start` один раз и получает постоянное меню.
2. Нажимает **🚀 Получить доступ**, выбирает пробный тариф и получает личный ключ на 1 день.
3. На экране активации нажимает **🔐 Подключиться к MTProto**.
4. В дальнейшем открывает ключ кнопкой **🔑 Мои ключи**, а срок действия — кнопкой **📅 Моя подписка**.

Пробный день выдаётся один раз. После его использования бот предлагает выбрать платный тариф.

## Обновление ключа клиентом

Клиент открывает **📅 Моя подписка** и нажимает **🔄 Обновить ключ**. При активной подписке бот выдаёт новую кнопку подключения, а старый ключ перестаёт работать после применения изменений proxy.

Новые ссылки выдаются в формате `ee...` с TLS-маскировкой. Ранее выданные ссылки `dd...` продолжают работать до обновления ключа.

Ключ можно обновлять не чаще одного раза в 10 минут.

## 🛰 SERVER_HOST и TLS_DOMAIN

`SERVER_HOST` и `TLS_DOMAIN` решают разные задачи:

- `SERVER_HOST` — публичный IP или домен VPS, который попадает в клиентскую ссылку как `server=...`. Меняется через `mtp` → `26`.
- `TLS_DOMAIN` — домен маскировки внутри `ee`-секрета, под который выглядит TLS-соединение. Меняется через `mtp` → `25`.

Для пользовательского `SERVER_HOST` домен должен иметь A-запись на IP VPS. При использовании Cloudflare требуется режим **DNS only** (серое облако): обычный Cloudflare proxy не проксирует MTProto без Spectrum.

На мобильных сетях чистый MTProto-secure-трафик из ссылок `dd...` может распознаваться DPI, из-за чего подключение затягивается или обрывается. TLS-режим выдаёт ссылки `ee...` и маскирует соединение под обычный HTTPS, поэтому подключение должно стать быстрее и стабильнее.

По умолчанию мастер использует `TLS_DOMAIN=www.microsoft.com` и резервные домены `www.cloudflare.com,www.apple.com,www.bing.com`. Существующую установку можно перевести на новый домен через `mtp` → `25` с созданием резервной копии.

`TLS_DOMAIN` должен иметь валидный TLS-сертификат и быть доступен в сетях ваших клиентов. Универсально лучшего домена для всех российских операторов нет: доступность и поведение DPI меняются по оператору и региону. Пункт `mtp` → `25` умеет выполнить TLS handshake с VPS для набора кандидатов перед выбором:

- `www.microsoft.com` — значение по умолчанию мастера установки
- `petrovich.ru` — официальный пример TeleMT
- `www.cloudflare.com`
- `www.apple.com`

Проверка с VPS подтверждает сертификат и handshake из дата-центра, но не заменяет тест через мобильные и домашние сети реальных клиентов в России. После смены домена рекомендуется проверить подключение на актуальных версиях Telegram для iOS, Android и Desktop: согласно FAQ TeleMT, в апреле 2026 года для Fake-TLS были важны обновлённые TLS-fingerprint клиентов.

После смены `SERVER_HOST` или `TLS_DOMAIN` активным клиентам нужно открыть **🔑 Мои ключи** и подключить новую ссылку.

Одна установка TeleMT использует один `SERVER_HOST`, основной `TLS_DOMAIN` и при необходимости список `tls_domains`. Для альтернативных ссылок список должен совпадать в `.env` (`TLS_DOMAINS`) и в секции `[censorship]` файла `telemt/config.toml` (`tls_domains`). Основная ссылка кодируется с основным `TLS_DOMAIN`, а резервные домены выдаются отдельно как альтернативные `ee`-ссылки. Plain MTProto (`dd...`) без TLS-маскировки проект намеренно не отдаёт как fallback.

## Ручные команды

Показать статус:

```bash
docker compose ps
```

Логи бота / TeleMT / бота поддержки:

```bash
docker compose logs -f --tail=120 bot
docker compose logs -f --tail=120 mtproto
docker compose logs -f --tail=120 support_bot
```

Пересоздать все контейнеры:

```bash
docker compose up -d --build --force-recreate bot support_bot mtproto
```

Для альтернативных Fake-TLS ссылок значения должны быть синхронизированы:

```env
# .env
TLS_DOMAINS=www.cloudflare.com,www.apple.com,www.bing.com
```

```toml
# telemt/config.toml, секция [censorship]
tls_domains = ["www.cloudflare.com", "www.bing.com"]
```

После ручного изменения этих значений примените конфигурацию:

```bash
docker compose up -d --build --force-recreate mtproto bot support_bot
```

CLI ключами через `proxy_manager.py` (внутри `bot`-контейнера, идёт через TeleMT HTTP API):

```bash
# Создать ключ (идемпотентно — возвращает существующий секрет)
docker compose exec bot python proxy_manager.py create tg_123456789

# Показать tg://proxy ссылку (с лучшим TLS-доменом из picker)
docker compose exec bot python proxy_manager.py link tg_123456789

# Обновить ключ клиента (только TeleMT)
docker compose exec bot python proxy_manager.py rotate tg_123456789

# Обновить ключ клиента по Telegram ID + синхронизировать SQLite (как в меню → 10)
docker compose exec bot python proxy_manager.py rotate-telegram 123456789

# Удалить ключ
docker compose exec bot python proxy_manager.py delete tg_123456789

# Список всех ключей
docker compose exec bot python proxy_manager.py list
```

Проверить TeleMT API напрямую:

```bash
docker compose exec bot python -c "import urllib.request,json; print(json.loads(urllib.request.urlopen('http://mtproto:9091/v1/users',timeout=3).read()))"
```

## 🔁 Перезагрузка из админ-панели бота

Кнопка **🔁 Перезагрузка системы** в админ-меню пересоздаёт основной бот, бот поддержки и MTProto-прокси. На время перезапуска клиенты могут потерять соединение примерно на 30 секунд.

Чтобы кнопка работала, один раз установите watcher на VPS: откройте `mtp` и выберите пункт `22` — **🛡 Установить watcher автоматического рестарта**.

Если watcher ещё не установлен, кнопка ничего не сломает: бот через 10 секунд покажет предупреждение с инструкцией по установке.

## 🛡 Состояние системы

Кнопка **🛡 Состояние системы** показывает в админ-меню, работают ли основной бот, бот поддержки, MTProto-прокси и автоматическая перезагрузка. Там же видны количество клиентов и подписок, свободное место, память и время последнего рестарта через бота.

Отчёт помогает быстро понять, нужен ли вход на VPS для проверки или восстановления сервисов.

Основной бот дополнительно проверяет TeleMT API в фоне. Если API недоступен более 30 секунд, администратор получает уведомление; после восстановления приходит отдельное сообщение. Читающие запросы к TeleMT API повторяются при кратковременном сетевом сбое, а операции создания и ротации ключей намеренно не повторяются автоматически, чтобы исключить неоднозначное состояние ключа.
